# Universal Export Design

**Date:** 2026-02-27
**Status:** Approved
**Audience:** Team & stakeholders (polished, not brochure-grade)

## Problem

specflow can only export epics and stories as flat markdown or YAML for Jira. Users need to export ALL entity types (initiatives, epics, stories, docs, decisions) in multiple formats, including rich HTML with Mermaid diagrams, syntax-highlighted code blocks, and a clean light theme.

## Design

### Approach: Renderer Pipeline

Entity → ExportNode tree → Renderer (MD / HTML / YAML)

A unified tree data model (`ExportNode`) represents any entity. Extractors load entities from the store into nodes. Renderers consume the tree and produce output in the target format.

### 1. Unified Data Model

```go
type NodeType string

const (
    NodeInitiative NodeType = "initiative"
    NodeEpic       NodeType = "epic"
    NodeStory      NodeType = "story"
    NodeDoc        NodeType = "doc"
    NodeDecision   NodeType = "decision"
)

type ExportNode struct {
    Type       NodeType
    Slug       string
    Title      string
    Status     string
    Priority   string
    Fidelity   string
    Labels     []string
    Body       string
    Acceptance []string
    Phases     []models.Phase
    Goal       string            // initiatives
    Context    string            // decisions
    Decision   string            // decisions
    Consequences string          // decisions
    Children   []*ExportNode     // nested entities
    Docs       []*ExportNode     // attached documents
    Decisions  []*ExportNode     // attached decisions
}
```

### Extractors

| Function | Input | Output |
|----------|-------|--------|
| `ExtractInitiative(store, slug, opts)` | initiative slug | Node with epic children, each with story/doc/decision children |
| `ExtractEpic(store, slug, opts)` | epic slug | Node with story children + docs + decisions |
| `ExtractStory(store, slug, opts)` | story slug | Leaf node with acceptance criteria |
| `ExtractDoc(store, slug, opts)` | doc slug | Leaf node with body content |
| `ExtractDecision(store, slug, opts)` | decision slug | Leaf node with context/decision/consequences |
| `ExtractAll(store, opts)` | - | Root node containing all initiatives, standalone epics, standalone stories |

Existing `ExportEpic()` / `ExportStory()` stay for backward compatibility (Jira skill).

### 2. Renderer Interface

```go
type Renderer interface {
    Render(node *ExportNode, opts RenderOptions) ([]byte, error)
}

type RenderOptions struct {
    IncludeBody bool
    IncludeDone bool
    Title       string
}
```

**Implementations:**

- **MarkdownRenderer** — recursive heading depth, acceptance as checklists, Mermaid passthrough, decisions as `<details>` blocks
- **HTMLRenderer** — self-contained single-file HTML with embedded CSS, Mermaid.js (CDN), Highlight.js (CDN), TOC, print-friendly CSS
- **YAMLRenderer** — backward compat with current `sf_export` output for Jira skill

### 3. CLI Interface

```
specflow export <slug>              # auto-detect type, default markdown
specflow export <slug> --format md
specflow export <slug> --format html
specflow export <slug> --tree       # include full subtree
specflow export --all --format html # entire project
```

| Flag | Short | Default | Description |
|------|-------|---------|-------------|
| `--format` | `-f` | `md` | Output format: md, html, yaml |
| `--output` | `-o` | auto | Output file path |
| `--tree` | `-t` | false | Include full subtree |
| `--all` | | false | Export entire project |
| `--no-body` | | false | Omit markdown body |
| `--exclude-done` | | false | Skip done stories |

Auto-detection: resolve slug by checking initiative → epic → standalone story → doc → decision (first match wins).

Backward compat: `specflow export <epic-slug>` produces same output as v1.7.0.

### 4. MCP Tool Updates

`sf_export` gains new parameters:

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `epic` | string | - | Epic slug (existing) |
| `story` | string | - | Story slug (existing) |
| `initiative` | string | - | Initiative slug (new) |
| `doc` | string | - | Doc slug (new) |
| `decision` | string | - | Decision slug (new) |
| `format` | string | `yaml` | Output format: yaml, md, html (new) |
| `include_done` | bool | true | Include done stories (existing) |
| `include_body` | bool | true | Include body content (existing) |
| `tree` | bool | false | Include full subtree (new) |

### 5. HTML Template Design

**Layout:** Header (title + TOC toggle) → content (recursive sections) → footer (generated by specflow + date)

**Styling:**
- Light theme: white background, dark text, subtle gray borders
- System font stack
- Status badges: colored inline pills (green=done, blue=active, gray=draft)
- Code blocks: light gray background, syntax-highlighted via Highlight.js
- Mermaid diagrams: rendered inline, centered, default light theme
- Decisions: collapsible `<details>` elements
- TOC: sticky sidebar on wide screens, dropdown on narrow
- Print: `@media print` hides TOC, clean B&W

**Dependencies (CDN):**
- Mermaid.js for diagram rendering
- Highlight.js for code syntax highlighting
- No other dependencies

**Offline option:** `--standalone` flag inlines Mermaid + Highlight.js source (~500KB).

### Why HTML instead of native PDF?

Native PDF in Go requires heavy dependencies (wkhtmltopdf, chromedp, or limited pure-Go PDF libs) that can't handle Mermaid. HTML gives:
- Zero Go dependencies
- Mermaid and code highlighting work natively
- Users can "Print → Save as PDF" from any browser
- Self-contained, shareable file

## What Breaks If Requirements Change

- **New entity type:** Add extractor + update renderers (tree structure handles nesting naturally)
- **New output format:** Add one Renderer implementation, wire into CLI/MCP
- **Offline-only requirement:** `--standalone` already planned
- **Team-specific Jira field mapping:** Jira skill handles this, not the renderer

## Non-Goals

- Native PDF generation (use browser print)
- Real-time preview / dev server
- Confluence export (separate concern)
- Custom themes (single light theme for now)
- Arbitrary filesystem file embedding (only specflow doc_refs)
